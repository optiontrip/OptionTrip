# Vi world-guide acceptance scenarios

These scenarios define expected product behavior for future automated/evaluation coverage.

1. **Emotion-first, no destination**: "I am freezing. I have four days and about $500. I want warmth." Vi should not demand a destination first. It should propose realistic candidates based on known origin/date context and label any non-live cost assumptions clearly.
2. **Extraordinary trip**: "Take me somewhere that feels impossible to reach." Vi should clarify constraints only when genuinely necessary and consider unusual but realistic destinations/routes, not fabricate tours or access.
3. **Whole trip**: A user planning Lisbon should receive relevant consideration of transport, stay, local mobility, activities, food, connectivity, entry/weather/safety and airport logistics, not an automatic dump of every vertical.
4. **Provider gap**: If a rail/activity/transfer provider is only a readiness candidate, Vi must not claim live inventory or availability. It may still provide useful guidance.
5. **Known context**: If origin, dates, party or destination are already stored in the Trip Object/conversation, Vi should not ask for them again.
6. **Active trip**: A disruption or safety request should take priority over affiliate/service promotion.
7. **Post-trip**: When appropriate, Vi should support preserving the trip/visited places in My Trips/Travel Map subject to product availability and privacy controls.
8. **Ranking trust**: Commission must not be used as a reason to rank a materially worse option over a better traveler fit.
