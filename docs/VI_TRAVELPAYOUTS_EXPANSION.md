# Travelpayouts expansion for Vi

Travelpayouts should be used as broadly as legitimate program access allows, but OptionTrip must distinguish affiliate-program availability from a live search/data integration.

## Current targets already represented in provider readiness

- flights: Travelpayouts / Aviasales
- hotels: Travelpayouts hotel capability
- rail/bus: Omio feed
- activities: Tiqets feed, WeGoTrip API, Viator dynamic feed
- connectivity: Airalo feed
- transfers: GetTransfer access/API

## Expansion queue

Review the current Travelpayouts program catalog and terms for legitimate paths covering rental cars, insurance, package tours, cruises and other travel-relevant categories. Then add each provider through the common lifecycle: access -> adapter -> normalized inventory/deep link -> health/freshness -> Vi/UI -> attribution.

Do not create fake adapters or hard-coded commercial inventory while access is pending.
